# Output contract

这个文件定义 annual-report-redflag-scanner skill 的输出结构。

目标不是“把读到的内容复述一遍”，而是：
**给出判断、说明证据、指出风险含义、保留待验证问题。**

排雷深度要求：
- 总体风险评级
- 必查覆盖表八行都要有状态（见 `references/mine-coverage.md`）
- 关键命中引用 `R0xx`（见 `references/forensic-rules.md`）
- 显式标注现金流量肖像类型名
- 必答三大前提
- 指标可得时补一句杜邦驱动
- 跟踪建议按 P0 / P1 / P2
- 不写估值区间，不给买卖建议

---

## Required structure

默认使用以下结构：

### 1. 一句话结论 + 总体风险评级
用 1-2 句话说清当前年报最值得关注的主线，并给出总体评级。

**总体风险评级**（四选一）：
- 极高风险
- 高风险
- 存疑
- 暂未发现重大财务疑点

好的写法：
- 这份年报的主线不是收入增长，而是“利润改善能否转成现金”的问题：净利润表现尚可，但回款与经营现金流没有同步增强。**总体风险评级：存疑。**
- 这家公司当前最需要警惕的是资本开支回报闭环不足：在建工程和固定资产持续扩张，但后续利润与现金回报仍需验证。**总体风险评级：高风险。**

避免：
- 公司整体经营稳定。
- 财报表现较好，值得关注。
- 只给评级不给主线，或只给主线不给评级。

### 2. 前置排雷结果
明确回答：
- 是否存在立即排除信号
- 若没有铁定排除信号，当前最大的排雷点是什么
- 命中硬伤规则时引用编号（如 R019、R020、R021、R030）

建议格式：
- **审计与重大风险**：……（如适用写 `R019` / `R020`）
- **是否存在立即排除信号**：有 / 暂未看到明确立即排除信号，但需重点跟踪……

### 3. 必查覆盖表
用一张表收口 `references/mine-coverage.md` 的分组。八行都要有，不能因为后面只展开少数雷点就把某行省掉。

| 分组 | 状态 | 依据 |
|------|------|------|
| 硬伤 | 未触发 / 命中 `R0xx` / 待验证 | 一句证据，或写明缺哪一节 |
| 货币资金 | 同上 | 含存贷双高或穷病；受限与利息匹配写进依据 |
| 应收 | 同上 | 增速差、账龄、坏账 |
| 存货 | 同上 | 含毛利率与周转是否同向变差 |
| 长期资产与商誉 | 同上 | 转固、减值、费用资本化 |
| 利润质量 | 同上 | 毛利率、费用率、扣非与非经常 |
| 现金流肖像 | 未触发规则时也要写类型名 | 类型名 + 符号，如奶牛型 `(+--)` |
| 联动 | 同上 | 三条闭环是否成立；规则外组合写在依据里 |

状态只用这三种：未触发、命中（带规则编号或「规则外」）、待验证。单年看不出「连续 N 年」时，可以标命中或倾向，依据里加「单年观察，连续性待验证」。

结构快照四项（生产资产/总资产、应收/总资产、现金/有息负债、非主业资产/总资产）数据够就附在「联动」行依据末尾；不够就写缺什么。不要为了凑四项通读年报。

### 4. 核心财务观察
只展开 3–5 条最重要的雷，不要把覆盖表再叙述一遍。

推荐主题池：
- 资产质量
- 利润质量
- 现金流质量
- 负债与资本结构
- 资本开支与回报闭环

每个主题建议写成：
- **观察**：发生了什么
- **含义**：这说明什么
- **证据**：来自哪些章节 / 附注 / 区段
- **规则**（如适用）：`R0xx`

若讨论现金流质量，必须显式写出：
- **现金流量肖像**：类型名 + 符号组合（如 `奶牛型 (+--)`）
- 类型名与符号以 `references/terminology-and-metric-conventions.md` 的 8 型定义为准

例如：
- **现金流质量**：净利润有增长，但经营现金流没有同步改善，说明利润现金含量仍需谨慎看待。现金流量肖像为蛮牛型 (`+-+`)。证据主要来自“合并利润表”“合并现金流量表”以及应收相关附注。规则：倾向触及 `R013`（单年观察）。

### 5. 重点风险清单
列出 2-5 条最值得继续跟踪的风险，不求多，求准。

按严重度分层（高 / 中 / 低），每条建议使用：
- **风险点**：
- **严重度**：高 / 中 / 低
- **规则依据**：`R0xx`（规则外则写「规则外」）
- **为什么重要**：
- **证据位置**：
- **当前判断**：已构成明确风险 / 倾向风险 / 仍待验证

例如：
- **风险点**：应收增长快于收入增长  
  **严重度**：高  
  **规则依据**：`R001`  
  **为什么重要**：可能意味着信用政策放松、渠道压货或收入确认偏前。  
  **证据位置**：合并资产负债表、应收账款附注、销售收现相关区段。  
  **当前判断**：倾向风险，需继续看账龄与坏账计提是否同步恶化。

#### 额外重大发现（可选但推荐）
若存在未落入 R001–R038、但实质重要的信号（跨指标联动、趋势恶化未触阈值等），单独列出 0–3 条；若无，可写「无」。

### 6. 三表联动判断
至少回答这三件事：
- 收入—应收—现金是否闭环
- 利润—经营现金流是否闭环
- 资本开支—折旧/回报是否闭环

建议格式：
- **收入—应收—现金**：闭环 / 部分闭环 / 不闭环，原因是……
- **利润—经营现金流**：……
- **资本开支—回报**：……
- **现金流量肖像**（若覆盖表或上一节未写清，此处必须补全）：类型名 + 符号

### 7. 三大前提判定
必须显式回答以下三个问题，缺一不可：
1. **利润是否为真？** — 经营现金流与收现能否大体验证账面利润
2. **利润是否可持续？** — 利润主要来自主业还是非经常/一次性项目
3. **维持利润是否需要大量资本投入？** — 资本开支与自由现金流是否持续侵蚀造血

每个问题用 1–3 句给出判断 + 关键证据；证据不足时明确写「待验证」，不要替公司补完逻辑。

### 8. 杜邦驱动（指标可得时）
若净资产、净利润、营收、总资产可得，用一句话说明 ROE 驱动：
- `ROE ≈ 净利率 × 总资产周转率 × 杠杆系数`
- 当前更像利润率驱动、周转驱动，还是加杠杆驱动？
- 公式口径以 `references/terminology-and-metric-conventions.md` 为准

若关键分母缺失，写「杜邦：数据不足，未计算」。

### 9. 待验证问题与跟踪建议
明确告诉用户：
- 现在还不能完全下结论的点是什么
- 若继续深挖，下一步最值得回查哪里
- 跟踪建议按优先级列出，每项写清具体指标

建议格式：
- **待验证问题**：……
- **建议下一步回查**：优先看……，其次看……
- **P0**：……（指标：……）
- **P1**：……
- **P2**：……

没有需要跟踪的级别可以写「无」，不要省略这三个标题。

## Citation style

不需要逐行密集引用，但应明确证据来自哪里；排雷命中应尽量带 `R0xx`。

推荐引用方式：
- 同级 `*.sections.json` 中对应的章节标题
- 报告章节名
- 附注科目名
- 规则编号 `R0xx`

表达方式示例：
- 证据主要来自“第三节 管理层讨论与分析”中的“主营业务分析”“资产及负债状况分析”，以及“财务报告-合并报表附注”中的应收账款、存货相关节点；倾向触及 `R001`、`R007`。

## Report write-out requirement

聊天里给出分析结论，不等于完成本 skill。

最终还应把完整 Markdown 报告写出：
1. 若用户提供 `output_path`，写到该路径
2. 若用户未提供，默认写到 `report_path.parent / <report_stem>.analysis.md`

写出的文件应与聊天里的核心结论保持一致，不要出现“聊天是一版、落盘是另一版”的情况。
落盘内容须覆盖本节 Required structure 的评级、必查覆盖表、三大前提、风险分层、肖像标注与 P0/P1/P2。

---

## Tone

- 直接、审慎、可复核
- 有证据时说清楚；证据不足时明确说“不闭环”或“待验证”
- 不要为了显得全面而把每个科目都讲一遍
- 不要因为用户要“分析”就把判断说得过满
- 不要输出买卖建议或收益承诺

---

## What good looks like

好的输出通常具备这些特征：
- 一眼能看出主线与总体风险评级
- 必查覆盖表八行都有状态
- 重点风险不超过 5 条，且带 `R0xx` 或「规则外」与严重度
- 现金流量肖像有明确类型名
- 三大前提均已显式回答
- 跟踪建议写到 P0/P1/P2
- 每个判断都能回到具体章节或附注
- 能区分“已确认风险”和“待验证异常”
- 明确指出接下来最值得继续看的区段
- 最终 Markdown 报告已按约定路径写出

---

## What to avoid

- 单纯摘要式复述财报目录
- 大量堆数字，但不解释数字之间关系
- 只说“要结合后续观察”，却不说具体该看什么
- 见到异常却不表态，只做模糊描述
- 没有区分“结论”“证据”“猜测”
- 有排雷命中却不引用规则编号
- 只在聊天中回答，却没有按约定写出最终分析 Markdown
