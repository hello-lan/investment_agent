# Output contract

这个文件定义 analyze-financial-report skill 的输出结构。

目标不是“把读到的内容复述一遍”，而是：
**给出判断、说明证据、指出风险含义、保留待验证问题。**

## Required structure

默认使用以下结构：

### 1. 一句话结论
用 1-2 句话说清当前年报最值得关注的主线。

好的写法：
- 这份年报的主线不是收入增长，而是“利润改善能否转成现金”的问题：净利润表现尚可，但回款与经营现金流没有同步增强。
- 这家公司当前最需要警惕的是资本开支回报闭环不足：在建工程和固定资产持续扩张，但后续利润与现金回报仍需验证。

避免：
- 公司整体经营稳定。
- 财报表现较好，值得关注。

### 2. 前置排雷结果
明确回答：
- 是否存在立即排除信号
- 若没有铁定排除信号，当前最大的排雷点是什么

建议格式：
- **审计与重大风险**：……
- **是否存在立即排除信号**：有 / 暂未看到明确立即排除信号，但需重点跟踪……

### 3. 核心财务观察
聚焦 3-4 个最重要主题，不要铺得太散。

推荐主题池：
- 资产质量
- 利润质量
- 现金流质量
- 负债与资本结构
- 资本开支与回报闭环

每个主题建议写成：
- **观察**：发生了什么
- **含义**：这说明什么
- **证据**：来自哪些章节 / 附注 / 区段

例如：
- **现金流质量**：净利润有增长，但经营现金流没有同步改善，说明利润现金含量仍需谨慎看待。证据主要来自“合并利润表”“合并现金流量表”以及应收相关附注。

### 4. 重点风险清单
列出 2-5 条最值得继续跟踪的风险，不求多，求准。

每条风险建议使用以下格式：
- **风险点**：
- **为什么重要**：
- **证据位置**：
- **当前判断**：已构成明确风险 / 倾向风险 / 仍待验证

例如：
- **风险点**：应收增长快于收入增长  
  **为什么重要**：可能意味着信用政策放松、渠道压货或收入确认偏前。  
  **证据位置**：合并资产负债表、应收账款附注、销售收现相关区段。  
  **当前判断**：倾向风险，需继续看账龄与坏账计提是否同步恶化。

### 5. 三表联动判断
至少回答这三件事：
- 收入—应收—现金是否闭环
- 利润—经营现金流是否闭环
- 资本开支—折旧/回报是否闭环

建议格式：
- **收入—应收—现金**：闭环 / 部分闭环 / 不闭环，原因是……
- **利润—经营现金流**：……
- **资本开支—回报**：……

### 6. 待验证问题与下一步回查方向
明确告诉用户：
- 现在还不能完全下结论的点是什么
- 若继续深挖，下一步最值得回查哪里

建议格式：
- **待验证问题**：……
- **建议下一步回查**：优先看……，其次看……

## Citation style

不需要逐行密集引用，但应明确证据来自哪里。

推荐引用方式：
- 同级 `*.sections.json` 中对应的章节标题
- 报告章节名
- 附注科目名

表达方式示例：
- 证据主要来自“第三节 管理层讨论与分析”中的“主营业务分析”“资产及负债状况分析”，以及“财务报告-合并报表附注”中的应收账款、存货相关节点。

## Report write-out requirement

聊天里给出分析结论，不等于完成本 skill。

最终还应把完整 Markdown 报告写出：
1. 若用户提供 `output_path`，写到该路径
2. 若用户未提供，默认写到 `report_path.parent / <report_stem>.analysis.md`

写出的文件应与聊天里的核心结论保持一致，不要出现“聊天是一版、落盘是另一版”的情况。

## Tone

- 直接、审慎、可复核
- 有证据时说清楚；证据不足时明确说“不闭环”或“待验证”
- 不要为了显得全面而把每个科目都讲一遍
- 不要因为用户要“分析”就把判断说得过满

## What good looks like

好的输出通常具备这些特征：
- 一眼能看出主线
- 重点风险不超过 5 条
- 每个判断都能回到具体章节或附注
- 能区分“已确认风险”和“待验证异常”
- 明确指出接下来最值得继续看的区段
- 最终 Markdown 报告已按约定路径写出

## What to avoid

- 单纯摘要式复述财报目录
- 大量堆数字，但不解释数字之间关系
- 只说“要结合后续观察”，却不说具体该看什么
- 见到异常却不表态，只做模糊描述
- 没有区分“结论”“证据”“猜测”
- 只在聊天中回答，却没有按约定写出最终分析 Markdown
